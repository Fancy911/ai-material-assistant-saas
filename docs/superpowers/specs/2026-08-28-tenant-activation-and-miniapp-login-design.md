# 包小印｜首租户登录、兑换与服务开通闭环设计

## 目标

将「包小印去水印」作为第一个真实 SaaS 租户，完成以下闭环：小程序用户以微信登录进入所属租户；兑换该租户创建的兑换码并获得可用次数；每次成功解析同步扣除用户次数与租户额度；租户可查询兑换人与剩余次数；平台可管理并观察租户的微信配置、服务开通状态与额度。

本设计延续已确认的双额度模型：用户 `pointsBalance` 即“剩余可用次数”，一次成功解析扣除 `TenantSetting.pointCost`；租户 `quotaRemaining` 是平台购买的上游调用额度。两者均不足或服务未开通时不得调用 Provider。

## 身份与配置边界

### 小程序用户登录

- 每个 `Tenant` 新增不可变、公开的 `publicCode`，首租户取值 `baoxiaoyin`；它只用于将小程序请求路由到对应租户，不是 Secret。
- 小程序构建配置持有该 `tenantCode`。启动时调用 `uni.login`，把微信 `code` 和 `tenantCode` 发送给 `/api/auth/wechat-login`。
- 服务端用 `tenantCode` 找到租户设置中的 AppID/AppSecret，并与微信 code2Session 交换 openid；同一 `(tenantId, openid)` 复用同一用户。
- 无真实微信 code 或开发者工具场景保留受限 Mock 登录，仅在 `AUTH_MODE=mock` 时开启，且仍只能落到指定 `tenantCode`。

### 租户微信配置

- 租户运营后台「设置中心」新增 AppID、AppSecret、服务授权码和配置状态区。
- AppID 可读取；AppSecret 仅首次输入完整值，服务端加密保存，后续仅显示掩码/末四位。
- 平台总端仅展示“已配置/未配置”和更新时间，不返回 AppSecret。
- 真实微信登录条件为 AppID 和 AppSecret 均已配置；否则小程序显示面向运营者的可理解提示，不伪造登录成功。

## 租户服务授权

### 开通码生命周期

- 平台总端为指定租户生成一个随机、一次性服务开通码。明文仅在生成响应中显示一次；数据库保存 hash、hint、状态、生成时间、使用时间与操作者。
- 租户管理员在设置页输入开通码。服务端只允许该码激活其所属租户；成功后标记该码已使用并记录审计日志。
- 平台可重新生成/撤销未使用开通码；新的有效码不会暴露任何上游 Provider Secret。
- 租户端只能看到“未开通 / 已开通 / 已暂停 / 已到期”与最近开通时间，不能读取开通码明文。

### 调用门禁

解析请求按以下顺序校验：租户存在且未暂停、未到期、租户服务已开通、所请求平台 capability 已启用、用户状态正常、用户次数足够、租户额度足够。任一失败均不调用 Provider、不扣次数、不扣额度。

Provider Key 仍仅由平台总端配置并加密保存在服务器。租户的开通码只是平台对租户的服务许可，绝不是智凌/残像 Key。

## 兑换与次数可观测性

### 小程序

- 登录完成后「我的」显示：当前剩余次数、每次扣除次数、累计成功解析、今日成功解析、租户公告与服务状态。
- 「兑换码」页面或弹层提交卡密，成功后刷新余额并提示本次增加次数；失败明确区分无效、已使用、停用、过期及不属于当前租户。
- 首屏和解析页在登录状态未就绪时不可提交解析；余额不足时引导到兑换码，不发起上游请求。

### 租户端

- 用户管理显示匿名用户标识、剩余次数、累计解析、最后活跃、状态，并支持查看单个用户的最近点数流水。
- 兑换码列表显示 code hint、次数、状态、创建/到期时间、兑换时间、兑换用户匿名标识和兑换后余额；绝不显示已创建卡密明文。
- 创建兑换码可设置次数、数量和可选有效期；返回的一次性明文卡密提供复制/导出。

### 平台端

- 租户列表和详情显示：租户名称、公开租户代码、状态、额度、可用平台、微信配置状态、服务开通状态、开通时间、用户数、今日调用/成功率。
- 平台总端可创建或重新生成该租户的服务开通码；该动作写入审计日志。

## 数据与接口

- `Tenant.publicCode`：唯一、不可变、小程序公开路由标识。
- `TenantActivationCode`：租户、hash/hint、状态、创建/使用时间、创建者与使用者管理员；每个租户同一时刻最多一个有效码。
- `TenantSetting` 复用既有 `appid`、`appsecretCiphertext`，补充/派生配置状态，不把 Secret 返回给前端。
- `POST /api/auth/wechat-login`：`{ code, tenantCode }`，返回用户 JWT、用户资料、租户品牌与服务状态。
- `POST /api/redeem`：以当前用户 JWT 所属租户原子兑换，返回新余额。
- `GET /api/me`：返回真实点数、使用统计、租户品牌、服务状态与每次成本。
- `GET /api/tenant-admin/users/:id`：租户管理员查看自身用户详情和流水。
- `POST /api/tenant-admin/settings/activate`：输入服务开通码。
- `POST /api/super-admin/tenants/:id/activation-codes`：总端生成一次性开通码。

## 安全与验收

- AppSecret、Provider Key、服务开通码明文均不写入静态前端、日志或审计元数据；前两者加密存储，开通码只存 hash。
- 兑换与开通码均由条件更新/事务消费，重复并发提交只有一个成功。
- Tenant A 的用户 JWT、兑换码、开通码不能影响 Tenant B。
- 自动化覆盖：真实/Mock 登录路由、未配置/未开通拒绝解析、跨租户开通码拒绝、一次性兑换、兑换后余额、租户用户详情、平台开通码生成。
- 手工验收：在微信开发者工具中使用首租户 AppID 登录，生成兑换码、兑换、解析一次、观察小程序余额、租户端兑换记录和平台端租户指标一致变化。

## 非目标

本轮不接微信支付、不将第三方 Provider Key 分配给租户、不实现多管理员审批，也不让租户自行开通未获平台授权的平台能力。
